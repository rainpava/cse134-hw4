One thing that I repeated manually a lot was copying and pasting the header, nav, and footer sections of the body. When I moved or renamed files, all of the tags that used relative pathing stopped working, such as the images and stylesheet links, so I had to also manually fix these in every file. This was especially annoying and prevalent in the guide directory, since these pathnames were slightly more verbose because of the nesting. When setting up the transitions from the cheese guide images to the hero images, writing the CSS for each family of cheese was also repetitive. Another thing that was tedious to do manually was ordering the navigation links for the cheese families correctly by remembering what was next and previous to the current cheese page I was writing.
If I had a tool, I would have used it to generate the copy and pasted components, as well as write CSS templates for styles and patterns that are frequently repeated with small variations. I also would use it to write href and src pathnames to manage relative paths when files are renamed, moved, or deleted, although I think this might already be an IDE extension I've used a while ago in VS Code. To address the navigation links issue, it would be useful to have a tool that manages "next/previous" style navigation automatically given the order of the content as input. Although these issues were relatively small in this homework, like the nested paths only adding "../" to pathnames or having only 4 families to write view-transition's for, these become much more annoying as projects scale, so these are issues that I would definitely like to see addressed by web components and SSGs.
